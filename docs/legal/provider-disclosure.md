# Atlas Provider Disclosure Draft — 12:40, 10.06.2026

## Status
Draft for legal/security review before website publication.

## Purpose
This document provides controlled website language for explaining that Atlas AI is a solution layer using third-party AI engines, cloud services, hosting providers, CMS tools and governance infrastructure where appropriate.

## Core disclosure
Atlas AI designs, configures, governs and supports AI work solutions. Atlas does not present itself as a proprietary foundation-model provider. Depending on the selected package, delivery mode, customer environment and risk classification, an Atlas solution may use one or more third-party providers such as AI model providers, cloud infrastructure, website/CMS providers, hosting providers, repository/governance tools, analytics services or business-support services.

## Provider-attributed evidence rule
Security certifications, data-processing terms, service availability commitments, data-residency options, support levels and compliance documentation belong to the provider and the specific service, plan, region, contract and configuration. Atlas may reference provider documentation only with attribution and with the relevant scope caveat. Atlas must not imply that Atlas itself holds a certification, formal SLA or data-residency commitment unless Atlas has its own documented evidence and contract basis.

## Approved public wording
`Atlas may use services from providers that document security, privacy, data-processing and availability controls. Applicability depends on the selected service, plan, region, contract and configuration. Atlas publishes Atlas-specific performance, reliability or security claims only when supporting Atlas evidence exists.`

## Provider caveat library

### OpenAI / ChatGPT / API
OpenAI documents security and privacy controls for relevant products and services. Applicability depends on the selected product, tier, data-residency setting, Trust Portal/customer access, contract and configuration. OpenAI Scale Tier SLA language must not be used as an Atlas uptime commitment unless the Atlas implementation uses eligible Scale Tier traffic under applicable terms.

### Google / Gemini / Google Cloud / Workspace
Google documents security/compliance controls, GDPR processing mechanisms and selected service SLAs for eligible services. Applicability depends on product, edition, region, contract and architecture.

### Microsoft Azure / Microsoft 365
Microsoft documents compliance reports and conditional availability terms for eligible Azure services and architectures. Atlas must not imply that Atlas is Microsoft-certified or that Azure availability commitments are automatically inherited by Atlas.

### GitHub
GitHub provides compliance documentation to eligible enterprise or organization owners. GitHub status information and GitHub compliance reports do not create an Atlas SLA.

### Wix
Wix publishes trust/compliance information and service-status information. The master review did not identify a formal public Wix uptime SLA. Wix uptime history must not be presented as an Atlas contractual uptime guarantee.

### Domeneshop
Domeneshop terms include a standard Data Processing Agreement for relevant hosting services. No public ISO/SOC certification or formal public SLA evidence is currently registered for Atlas claim purposes.

### AWS
AWS documents compliance programs, data-processing terms and service-specific availability terms. Each AWS service has its own SLA; Atlas must confirm service, region, architecture and contract before using AWS documentation as evidence for any Atlas-facing claim.

## Data residency caveat
Data storage and data processing location depend on the selected provider, service, plan, region, contract, support model, subprocessor chain and delivery configuration. Atlas must not state that all data is stored in Norway or never leaves the EEA unless the exact delivery path is mapped and approved.

## Managed Secure caveat
Managed Secure is a qualified architecture-review path for confidential and control-sensitive workflows. Secure-delivery claims remain evidence-gated until identity, access, logging, revocation, private storage, backup/restore and incident-response evidence is complete and approved.

## Form/intake boundary
Ordinary public Wix forms are low-risk qualification only. They must not request confidential, restricted, regulated or customer-sensitive files. Sensitive materials must be routed only after qualification and through a controlled secure path.
