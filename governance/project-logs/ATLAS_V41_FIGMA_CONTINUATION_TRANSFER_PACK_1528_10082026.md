## Canonical Atlas Figma v4.1 configuration

These owner-approved rules apply by default to future configuration and adjustment work until explicitly superseded:

### Canvas and layout

- Slide canvas: `1920 × 1080 px`.
- Principal side margins: approximately `104 px`.
- Standard full-width content: approximately `1,712 px`.
- Global grid/card rhythm: `32 px`.
- Default card padding: `32 px`.
- Preserve documented source-specific exceptions for intentional split layouts, image bleeds and dense diagrams.

### Typography

- Display/principal/card headings: `Roboto Slab`.
- Body copy, labels and controls: `Roboto`.
- Hero principal heading: retain the explicitly approved hero size; established Home/Tjenester-family baseline is `64 px` where applicable.
- Non-hero principal page/section headings: `Roboto Slab Regular, 50 px, 118% line height`.
- The `118%` rule applies to principal non-hero headings only.
- Body text, list text and text inside boxes must preserve or explicitly reproduce the source-specific line height and paragraph/list spacing. Never propagate the heading line-height value into body/list text without source evidence.
- Preserve deliberate source line breaks.
- Use either native Figma list formatting or literal bullets, never both.

### Corner-radius taxonomy

- Standard content cards/boxes: `6 px` on all four corners.
- Pricing/status panels: `6 px`.
- Information/warning/neutral callouts: `6 px`.
- Category/section labels: `4 px`.
- Primary/secondary CTA buttons: `4 px`.
- Full-slide backgrounds and edge-to-edge image regions: `0 px`.
- Circular/intentional image masks: preserve approved source crop geometry.
- Do not retain mechanically scaled Gamma/PPTX radii such as approximately `18–50 px` without explicit approved evidence.

### Controls and images

- Raster/image-filled CTA buttons must be rebuilt as editable Figma frames/text.
- Raster card surfaces should be rebuilt as editable Figma structures where the card is a UI/content container rather than intentional artwork.
- Validate every image-bearing node on every slide: `IMAGE` fill, non-empty hash, opacity, expected `CROP`/`FIT`, clipping, finite transform, positive dimensions, slide-bound containment and rendered focal-subject/crop.
- Preserve `CROP` for photographs and approved diagram/infographic regions.
- Use `FIT` for line/information/warning icons when source intent requires the complete icon to remain visible.
